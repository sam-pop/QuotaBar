1 · Menu bar

How a third, OpenAI account reads at a glance

Today each account is a colored dot plus a prefix. The question is whether the provider needs its own mark in 26 points of height.

1a Prefix only recommended

The auto-derived prefix comes from the label ("Codex" → C), which the user can override anyway. Nothing new to learn; the bar stays the same width per account.

1b Provider glyph replaces the dot

The identity color stays, the shape carries the provider: a star for Claude, a hexagon for OpenAI. Readable, but it changes the single-account bar too, and 9-point glyphs blur on non-Retina displays.

What changes, what doesn't

  • ✓PEAK still means "closest to its cap". Codex leads the 5-hour row at 70%, which is exactly the contention you'd want flagged.

4 · Login expiry

What an OpenAI column says about its login

Anthropic tells us when the refresh token dies (about 28 days), so Claude columns can count down. OpenAI's token response has no such field, only a 10-day access token that auto-renews. The honest states are below.

Personal Claude
● Updated 12s ago · login expires in 12d
Personal Claude
⚠ Login expires in 2d
Codex OpenAI
● Updated 12s ago
Codex OpenAI
✕ Log in again refresh was rejected

Proposal

  • ✓No countdown for OpenAI. Showing one would be a guess. The "Updated …" line stays, and nothing pre-expiry is shown.
  • ✓Same failure affordance. A rejected refresh flips the column to the existing red "Log in again" pill, which re-opens the OpenAI browser login with the account's email pre-filled where OpenAI allows it.
  • ✓Pre-expiry notifications stay Claude-only until OpenAI exposes a refresh-token lifetime.

My recommendation

1a prefix-only in the menu bar, 2 a peer column with a provider chip, 3·1 a menu on the existing button, and 4 no fake countdown for OpenAI. Together that touches the column header, the footer button, and the login model, and leaves the matrix, sparkline, notification, and menu-bar composition code alone.
